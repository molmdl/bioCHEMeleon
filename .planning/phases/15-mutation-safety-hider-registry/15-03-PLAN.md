<objective>
Build `vmd/lib/backup.tcl` — the mol bridge that snapshots viewpoint + rep list (and the original PDB path) before mutation and restores them on a NEW molid after `mol delete` + `mol new`. The v2 wrinkle: molid changes on reload and reps/viewpoint do NOT survive (`mol delete`+`mol new` resets to 1 default Lines rep + load-default viewpoint). `restore` owns the FULL cleanup cycle (`mol delete $molid_to_delete` — the LIVE game_molid passed by cleanup, NOT the dead original — + `mol new original` + re-apply reps + restore viewpoint) — atomic, returns the new molid. `apply` is the state-only half (re-apply reps+viewpoint to an EXISTING molid, no mol ops) — game.tcl calls it on the game_molid after `mutation::mutate` to satisfy SC4's forward path.

Purpose: SC2 (cleanup restores the original exactly — same atom count, same reps, no hider residue) and SC4 (viewpoint + rep list saved before mutation, restored on the new molid — viewmaster round-trip). backup.tcl owns the restore-reload; mutation.tcl owns the forward mutate-reload; game.tcl owns neither `mol delete`/`mol new` (it calls backup::apply — no mol ops — and backup::restore). backup is standalone (sources nothing) so it does NOT reverse the dependency direction onto demos/registry.

Output: New `vmd/lib/backup.tcl` (3 exported procs) + new `vmd/smoke/phase15_backup_smoke.tcl` (headless smoke, BCHM_SMOKE_RESULT PASS=1).
</objective>
