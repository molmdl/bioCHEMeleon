THE CONTRACT (research pick doc — authoritative, do NOT re-derive):
- PRIMARY mechanism: `trace add variable ::vmd_pick_event write ::biochemeleon::pick_bridge::_on_event`. The callback signature MUST be `{args}` — it receives (name1 name2 op), NOT (molid atom). A wrong signature makes VMD's variable WRITE ITSELF FAIL and the pick is LOST (probe3).
- Inside the handler: `global vmd_pick_atom vmd_pick_mol` — vmd_pick_atom is the 0-based atom INDEX (registry key), vmd_pick_mol is the molid. There is NO vmd_pick_molecule/vmd_pick_state/vmd_pick_selection (guard with info exists).
- Pick-atom mode = `mouse mode pick 2` (resolves to labelatom). FORBIDDEN: `mouse mode 4 2` (= userpoint in the 1.9.3 binary — the UG table is stale), `mouse mode pick 0` (= query). Rotate = `mouse mode rotate`.
- `::vmd_pick_atom_callbacks` is a PHANTOM (not in UG, not in shipped scripts, not pre-created). At most a no-op compat shim; NEVER gate correctness on it.
- Defaults (vmdinit.tcl:279-280): `vmd_mouse_mode` = rotate, `vmd_mouse_submode` = -1. Mode-set is NOT atomic (probe1: failed set still writes submode) — restore failures fall back to `mouse mode rotate`.
- Labels: every pick-atom click creates a label; `label list Atoms` format is `{{molid index} value showstate}`; `label delete Atoms <n>` RENUMBERS — delete from the END only, down to the baseline count; never `label delete Atoms all` (nukes user labels).
- Duplicate trace = double fire (probe3; Tcl does not dedupe) — guard with an `active` flag + trace remove BEFORE trace add.
- Every handler body wrapped in `catch` with a `vmdcon -err` report — NEVER propagate (an error in the trace proc blocks VMD's own write).
- Contract with game.tcl (Plan 16-08, same-wave): `_on_event` calls `::biochemeleon::game::on_pick $vmd_pick_atom` — ONE argument (the index). game.tcl stashes the current game_state itself; the bridge carries no game state.
- File conventions: sources NOTHING (like backup.tcl); namespace `::biochemeleon::pick_bridge` (file/namespace parity); Tcl 8.5; braced expr; one variable per line.
- Smoke conventions: model on `vmd/smoke/phase15_smoke.tcl` (failures/_bail/catch-per-step/marker/exit). The smoke may define a RECORDING STUB `proc ::biochemeleon::game::on_pick {idx} { lappend ::PICK_LOG $idx }` — it validates DELIVERY, not the scoring logic (that is 16-08/capstone).
