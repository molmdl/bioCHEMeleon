## 1. Executive Summary

Phase 17.1 needs a per-rep contract for the 10 GAME_REPS (`Lines VDW Licorice CPK Cartoon NewCartoon Trace Tube Points DynamicBonds`, `vmd/lib/setup_state.tcl:10`). This research probed every claim headlessly and found: **all 10 style names are valid EXACTLY as spelled, all round-trip through the combined-braces `molinfo` read-back EXACTLY, and every one accepts the sentinel selection (`resname GAM and beta < 0 and user2 < 1`) with Element coloring** — the GAME_REPS list is viable as-is, and **nothing viable is missing** (the 3 borderline reps — Bonds, Ribbons/NewRibbons, Beads — are deliberate redundancy/niche exclusions, all trivially addable later because they reuse existing generators).

The single biggest methodological finding: **`render Tachyon` works in `-dispdev text` mode** — headless VMD exports the exact scene geometry (spheres/cylinders/triangles with resolved RGB colors) that OpenGL would draw. This turns "does rep X render a lone GAM atom?" from a guess into a counted, parsed measurement, and it is the recommended verification primitive for all 17.1/17.2 generator plans. Using it, this research resolved the per-rep render matrix empirically, including two discoveries that change generator design:

1. **The both-endpoints rule:** bond-style reps (Lines, and DynamicBonds probed; Bonds/Licorice implied) draw a bond only when BOTH endpoint atoms are in the rep's selection. A hiders-only rep under Lines draws **radius-0 dots**, not bonds — so bond-style *hider* reps must include the bonded real neighbor in their selection (or rely on the scene's own `all`-selection rep to draw the bond, which the current hiders.tcl architecture already does).
2. **The GAM-name color trap:** under default **Name** coloring, an atom named `GAM` resolves to **salmon (1.0, 0.6, 0.6) — it does NOT blend**. Blending works through the **Element** coloring method: an element-C hider resolves to cyan (0.25, 0.75, 0.75) — byte-identical RGB to real carbons under Name coloring. This confirms hiders.tcl's blend premise with pixel-level evidence and makes "hider element = C + `mol modcolor Element`" a hard generator rule (or, alternatively, naming hiders `CA`/`C` so Name coloring blends).

Also verified: the GAM backbone residue **is classified as `protein`** (VMD classifies by backbone atom names + connectivity, not resname) and its CA **joins the CA trace** — Trace on a protein selection drew the CA4→CA5(GAM) segment (empirical), which de-risks the Cartoon/NewCartoon/Trace/Tube family (17.2). `DynamicBonds`' default cutoff is **3.0 Å** (not 1.1) with a strict `<` test — generators must pass an explicit ~1.6 cutoff to avoid spurious bonds. And a failure-mode trap: **`mol modstyle` with an invalid style name NEVER raises a tcl error** — it prints `ERROR)` to the VMD console and silently no-ops (or fuzzy-matches), so style validation must be done by read-back comparison, never by `catch`.

**Primary recommendation:** Keep the 10-rep GAME_REPS list unchanged. Split generators 6+4: **17.1 = Lines, VDW, Licorice, CPK, Points, DynamicBonds** (single-atom hiders; VDW's machinery is already Phase-16-proven), **17.2 = Cartoon, NewCartoon, Trace, Tube** (shared GAM-backbone-residue splice machinery; Trace/Tube are the SS-independent sidestep). Enforce: canonical style spellings + read-back verification, element-C hiders + Element coloring, explicit DynamicBonds cutoff, and ONE consolidated GUI human-verify checkpoint covering all 10 reps.

### Per-rep notes (evidence detail)

**Lines** — bond rep; Tachyon shows half-cylinders (rad 0.002) for bonds whose BOTH endpoints are in the selection (same-color halves merge to one cylinder in export: 3 internal bonds → 5 cylinders, colors blue1/cyan3/red1 exactly matching the N-CA/CA-C/C-O half-bond decomposition), and **radius-0 dot spheres at every selected atom whose bond partners are all unselected** (4 dots = 2 lone hiders + 2 hiders bonded to unselected reals) `[PROBE p6b/p7 lines_halfsel: 0 cyl + 8 dots]`. UG: Lines ≈ Bonds with lines instead of cylinders `[CITED node56/57]`.

**VDW** — spheres at every selected atom, radius = VDW radius × scale (bare form = res 8.0, scale 1.0; a 3rd param is rejected, see §6) `[PROBE p1]`. UG: radius determined from the atom's element; **VMD guesses atom type by the FIRST LETTER of the atom name when the element column is absent** ("HG" → hydrogen) `[CITED node61]` — one more reason hiders must carry a real element.

**Licorice** — spheres sized to the bond radius + bond cylinders `[CITED node63]`; lone GAM atom draws its (bond-sized) sphere with no cylinder `[PROBE]`.

**CPK** — VDW spheres scaled down (measured 0.25×, the CPK default) + bond cylinders `[CITED node62]`; "if the radii … are too small, they will not be drawn" `[CITED node62]`.

**Cartoon / NewCartoon** — STRIDE-based SS rendering (helix cylinders ≥3 residues / sheet ribbons / coil tube) `[CITED node69]`; NewCartoon renders helices as curved ribbons and its B-spline "does not always pass through the Cα positions" `[CITED node70]`. Headless: STRIDE failed today (see Open Questions) so probes rendered all-coil tubes; the GAM residue's CA **was included in the trace geometry** (18 spline cylinders / 42 mesh triangles) `[PROBE]`. Pick target is the Cα position `[CITED node69]` — the same atom the registry keys on.

**Trace / Tube** — CA-trace reps, SS-independent (the 17.2 sidestep option) `[CITED node65/66]`. Trace connects "the alpha-carbon atoms of successive residues by cylindrical segments"; UG explicitly notes polymer trickery: "people … can fake their structure by naming everything 'CA' … and then using Trace" `[CITED node65]` — favorable precedent for GAM-residue splicing.

**Points** — one point per atom, no bonds `[CITED node60]`; exports as tiny spheres `[PROBE]`. Trivial generator; the open question is click-through of a near-pixel target `[GUI]`.

**DynamicBonds** — distance-based bond search per active frame `[CITED node58]`. Probed cutoff semantics on isolated pairs: `DynamicBonds <cutoff>` bonds pairs with distance **strictly < cutoff**; the sweep measured 1 pair @1.3, 2 @1.6, 2 @1.8, 3 @2.0, 4 @2.2, 5 @2.5, 6 @3.0, 7 @3.5 (of 8 pairs at 1.2–4.0 Å) and **bare ≡ 3.0** — the default cutoff is 3.0 Å `[PROBE p7]`. Cylinders are bond-radius (0.0099 in export units ≈ Bonds-style sticks), not Lines hairlines `[PROBE]`. Consequence: at the default 3.0 cutoff a GAM residue shows **spurious bonds** (measured intra-residue pairs at 2.28/2.81/2.93 Å drawing as bonds) — hider reps must pass an explicit ~1.6 cutoff `[PROBE]`.

## 4. Color-blending matrix (resolved RGB, Tachyon-parsed)

VMD's default scene coloring is **Name**; its table is `vmd-ref/scripts/colordefs.dat`: the Name category maps single-letter prefixes **H→white, O→red, N→blue, C→cyan, S→yellow, P→tan, Z→silver** (plus Drude LPA/LPB) — **there is no G entry** `[CITED]`. Rendered colors measured from exclusive-selection Tachyon exports `[PROBE p5]`:

| Atom | Name method | Element method | Resname method |
|------|-------------|----------------|----------------|
| real CA / C (name C*) | **cyan (0.25, 0.75, 0.75)** | cyan (element C) | (by residue) |
| real N | blue (0.0, 0.0, 1.0) | blue (element N) | (by residue) |
| real O | red (1.0, 0.0, 0.0) | red (element O) | (by residue) |
| **hider named "GAM" (element C)** | **salmon (1.0, 0.6, 0.6) — DOES NOT BLEND** | **cyan (0.25, 0.75, 0.75) — blends** | gray (0.6, 0.6, 0.6) — does not blend |
| GAM-residue CA (name "CA") | cyan (name-based, blends) | cyan | gray |

**Blend rules for generators (all `[PROBE]` unless noted):**

1. **Hider reps must use `mol modcolor Element`** (with hider element = C, which `mutation.tcl` already writes, `HID_ELEMENT "C"` `[REPO]`) — the hider's cyan then equals the real carbons' Name-cyan **byte-for-byte**. This is the same premise hiders.tcl already ships (`[REPO] hiders.tcl header, probes F6/F7`) now confirmed at resolved-RGB level.
2. **Never rely on Name coloring for GAM-named hiders** (salmon giveaway). Two viable alternatives: (a) Element method (above); (b) name hider atoms `CA`/`C` so Name-method scenes blend — but naming hiders `CA` makes them match `name CA` selections (they already appear in `name CA` counts `[PROBE p2: 7 CAs]`), which is acceptable but must be a conscious choice.
3. **Resname/ResType are anti-blend for GAM** (gray; GAM is not in the Restype residue tables) — reserve them for debug/reveal views, not blending.
4. **Bonds draw as two half-bonds, each colored by its nearest atom** `[CITED UG node85 Table 6.3 preamble]` — a hider element-C half renders cyan next to a real N's blue half; on close inspection the boundary is visible `[GUI]` (v1 had the same tradeoff; copying a per-atom color is impossible in VMD — no per-atom color field `[CITED node85: color is per-rep method]`).
5. **ColorID requires its index argument** (`mol modcolor $r $m ColorID 7`); bare `ColorID` prints `ERROR) Incorrect atom color method command 'ColorID'` and silently no-ops `[PROBE p3]` — the found-rep green pattern from hiders.tcl is correct as written `[REPO]`.
6. All 19 probed color methods are valid for `mol modcolor`: Name, Type, Element, Resname, ResType, Chain, Segname, Molecule, Structure, Index, User, User2, Beta, Occupancy, Mass, Charge, Pos, Throb, ColorID `[PROBE p3]`; the UG adds ResID, Conformation, PosX/Y/Z, User3/4, PhysicalTime, Timestep, Velocity, Fragment, Backbone, Volume `[CITED node85 Table 6.3]`.

## 6. Rep-management semantics the generators must code against (all `[PROBE]`)

1. **`catch` NEVER fires on a bad style.** `mol modstyle 0 $m BogusStyle` returns OK, prints `ERROR) Unknown atom representation command 'BogusStyle'.` to the VMD console only, and leaves the style unchanged. Worse, near-miss names **fuzzy-match**: `NewCartoons` errored the same way but `vdw`-style variants show the read-back keeps whatever the rep already had; `Point`/`DynamicBond` are invalid (error + no-op) while `Points`/`DynamicBonds` are valid. → **Validation = modstyle, then read back `molinfo get {rep $i}` and string-compare to the requested name.** Never validate by catch. (Probe suites: same rule — scan output for `ERROR)`, a clean exit proves nothing.)
2. **Read-back preserves the as-typed case:** `mol modstyle … vdw` reads back `vdw`; `LINES` reads back `LINES`. `demos::get_active_reps` uses `lsearch -exact` against the canonical GAME_REPS and **misses lowercase reps** (`[PROBE p4]`: a `vdw` rep was not detected). The VMD GUI writes canonical spellings, so user scenes are safe; **our own code must always pass canonical spellings** (define the 10 names once in the pure layer and never hand-type them). Optional hardening: case-insensitive compare in `get_active_reps` (small demos.tcl change; planner's call).
3. **Rep names are stable; indices renumber.** After `mol delrep 2`, repnames read `rep0 rep1 rep3 rep4` at indices 0–3 — names stay glued to their reps while indices shift; `mol repindex $m rep3` resolves the current index (2). Track by name, resolve with `mol repindex`, exactly as AGENTS.md mandates `[PROBE p4]`.
4. **`mol addrep` inherits the current `mol representation/selection/color` defaults** set beforehand: after `mol representation Points; mol selection {resname GAM}; mol color ColorID 3`, the added rep read back `Points | resname GAM | ColorID 3 | Opaque` — the viewmaster/clonerep pattern works verbatim `[PROBE p5; REPO PITFALLS Integration Gotchas]`. (Generators may use either this or addrep-then-mod*; both verified.)
5. **Shown-state:** `mol showrep $m $i` (no on/off arg) is the query form, returns 0/1 `[PROBE p5; CITED viewmaster.tcl:259]`. `molinfo get "{shown $i}"` is INVALID ("cannot find molinfo attribute 'shown 1'") `[PROBE p4]`.
6. **Parameter forms accepted (bare / with args), silent-reject otherwise** `[PROBE p1]`: Lines 0; Bonds 0; VDW 0 or `res scale` (3 args rejected: `Incorrect atom representation command 'VDW 8.0 1.0 2'`); CPK 0 or 4 args; Licorice 0; Points **0 only** (`Points 8.0 1.0` rejected); Trace 0; Tube 0 or 2; Cartoon 0; NewCartoon 0; DynamicBonds 0/1/2 (cutoff [resolution]). Note the rejected forms also do NOT raise tcl errors — same console-only `ERROR)` + no-op behavior.
7. **`mol ssrecalc $m`** exists (usage text) `[PROBE]`; today it ran but STRIDE's output file went missing (`ERROR) Call to Stride program failed.`) — see Open Questions.
8. **PDB column trap (re-confirmed):** `beta = -999.00` needs 7 chars (`-999.00`) and **overflows the 6-col B-factor field**, shifting segid to read `GAM` and the element column to garbage (element `X`) `[PROBE p2 v1]`. `mutation.tcl` already mandates `%6.1f → "-999.0"` for exactly this reason (`[REPO] mutation.tcl:69-73, probe2b.log`) — 17.1's generator work must reuse that format string, and any new PDB-writing path must assert len==78 with segid at cols 73–76.
9. **Hider element drives VDW radius and blend:** element-C hiders get radius 1.70 == real carbon (N 1.55, O 1.52) `[PROBE p2]`; without a valid element column VMD guesses the type from the name's first letter (`[CITED node61]`) — GAM would mis-classify. Keep `HID_ELEMENT "C"` `[REPO]`.

```tcl
exit
```

Assertion hints from this research: a **salmon color in any hider scene = Name-coloring leak** (fail); **cylinder counts changing between `DynamicBonds` bare and `DynamicBonds 1.6` = spurious-bond leak** (fail); `points` scenes must contain one primitive per hider; trace-family scenes over `{protein}` must contain the segment(s) touching the GAM residue's CA (the 17.2 acceptance proxy). Note `-e` scripts CONTINUE after errors (the REPTABLE bug in probe v1 was exactly this) — always scan the full output for `ERROR)`/`bad switch`, and end scripts with `exit` (VMD otherwise sits at its interactive prompt and the WSL runner hangs).

## 8. GUI human-verify checklist proposal (ONE consolidated checkpoint)

Text mode cannot fire picks or run STRIDE reliably, so blend quality / pick-through / SS shape must be human-verified — but it fits in **one session** (a mixed-rep round on 1znf, plus the GAM fixture if needed), not per-rep checkpoints:

3. **Found-marking visibility per rep:** after a find, the found rep (ColorID 7) must be visibly distinct for that style — notably for Lines/DynamicBonds decide whether a green *dot* suffices or the partner-in-selection green *bond* is wanted (see Pitfall P-3).

## 9. Common Pitfalls (new/confirmed for 17.1)

- **P-1. Silent style failure.** `catch` around `mol modstyle` is a false-pass machine (`[PROBE]`). Validate by read-back equality; in probes, grep for `ERROR)`.
- **P-2. Case drift breaks lock-scene.** Non-canonical spellings read back verbatim and are invisible to `get_active_reps`' `lsearch -exact` (`[PROBE p4]`). Single source of truth for the 10 names; never retype them.
- **P-3. Both-endpoints rule for bond reps.** A hiders-only Lines/DynamicBonds rep draws **dots, not bonds** (`[PROBE p6b/p7]`). Either include the bonded real neighbor in the hider rep's selection (full bond draws — and on found-marking the whole bond recolors green, a deliberate visual tradeoff) or rely on the scene's own all-selection rep to draw the bond and keep hider reps as overlays (current hiders.tcl architecture). Decide once, in 17.1, for all bond styles.
- **P-4. GAM-name color leak.** Name coloring renders GAM-named atoms salmon (`[PROBE p5]`). Hider reps use Element coloring + element C; never ship a hider rep with `modcolor Name` on GAM-named atoms.
- **P-5. DynamicBonds default cutoff = 3.0 Å.** Spurious 2.3–2.9 Å bonds appear at default (`[PROBE p7]`). Always pass an explicit cutoff (~1.6) and the hider offset must be strictly < cutoff (strict `<` test).
- **P-6. beta-column overflow.** Writing `-999.00` (7 chars) into PDB cols 61–66 corrupts segid/element (`[PROBE]`, cross-confirm `[REPO] mutation.tcl:69-73`). Reuse the `%6.1f` format; assert 78-char records.
- **P-7. Hider double-bonding.** A 1.5 Å hider near a CA bonded to TWO real atoms (CA and C) (`[PROBE p2]`). Placement offsets should target one neighbor at a time, or accept multi-bond visuals deliberately.
- **P-8. Headless STRIDE is unreliable.** `mol ssrecalc`/Cartoon rep creation triggered `Call to Stride program failed` today (p2/p6) although Aug-22 probes recorded STRIDE SS codes (`[REPO] FEATURES.md Verification Log`). Do not headless-assert SS-dependent cartoon shapes; GUI-verify (see Open Questions).
- **P-9. Probe-script self-inflicted errors.** `[$i]` inside a double-quoted `puts` is command substitution ("invalid command name 0") and `atomselect $m "txt" num` is not a valid form (use `[$s num]`); `-e` scripts continue past errors, and without a trailing `exit` VMD sits at its prompt and the runner hangs. (All three hit in this research's probes v1.)

## 10. Don't Hand-Roll

| Problem | Don't build | Use instead | Why |
|---------|-------------|-------------|-----|
| "Did the rep get created?" | `catch {mol modstyle ...}` | read-back string-compare via combined-braces `molinfo` | catch never fires on bad styles (`[PROBE]`) |
| "What does this rep draw?" | guesswork / docs-only | `render Tachyon` headless + primitive/color parse | exact scene geometry + resolved RGB, no GL needed (`[PROBE]`) |
| "Is the hider blended?" | per-atom color copying (v1 habit) | Element method + element-C hiders | VMD has NO per-atom color field; Element cyan == Name cyan for C (`[PROBE p5; CITED node85]`) |
| Found-recolor per rep | new rep per found hider | user2 partition + ONE found rep per style (hiders.tcl pattern generalized) | the two-rep split is the verified per-atom-recolor workaround (`[REPO] hiders.tcl`) |
| Bond search for placements | hand distance loops in tcl | VMD load-time autobond + `atomselect ... getbonds` | bonds are inferred on load; getbonds verifies (`[PROBE p2]`) |
| Style list maintenance | hardcoding style strings in generators | `GAME_REPS` from the pure layer | canonical spellings + case pitfall (`[PROBE p4]`) |
