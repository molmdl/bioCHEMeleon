## 0. Executive Summary

The simple-tier hider is a **real PDB ATOM record** placed 1.2–1.6 Å from a real anchor atom, carrying the **anchor's element and name** plus the sentinel fields. VMD's loader then does the rest: on `mol new`, a distance search automatically bonds the GAM atom to the anchor (and to any other atom within cutoff — cross-chain, cross-segid, cross-resname alike), and every atom-centered rep renders it identically to a real atom of that element. The single most consequential discovery is the **empirical bond law, verified at boundary precision on 1znf-scale synthetic PDBs**:

> **VMD 1.9.3 bonds two atoms iff `distance < 0.6 × (r_i + r_j)`**, with VDW radii C=1.70, N=1.55, O=1.52, S=1.80, H=1.00, unknown-element X=1.50.
> Verified boundaries: C-C bond@2.03/no-bond@2.05 (cutoff 2.040); C-N 1.93✓/1.97✗ (1.950); C-O 1.91✓/1.95✗ (1.932); C-S 2.08✓/2.12✗ (2.100); C-H 1.60✓/1.65✗ (1.620). [VERIFIED — probes B/C]

Second discovery: **headless VISUAL verification is possible.** `render Tachyon <file>` works in `-dispdev text` and exports the full primitive scene (spheres/FCylinders with per-primitive Color RGB and Rad). Selection-isolated renders + diffs proved, headlessly: a corrected hider record renders as **exactly the same sphere radius (Rad 0.094504 == real carbon) and same color (cyan)** as the real anchor under VDW/Name coloring; Lines draws a bonded hider as line stubs; **Lines/Licorice draw UNBONDED atoms as tiny dot-spheres** (a lone hider is *not* invisible in VMD, unlike PyMOL v1); **DynamicBonds ignores the bond list and computes its own bonds from its cutoff param (default 3.0, inclusive)**; CPK = spheres + bond cylinders; Points = one dot per atom. [VERIFIED — probes E/G/H/J/K]

Third: the **element field is load-bearing**. A GAM record with a blank/mangled element degrades silently to element X: radius 1.50 (12% smaller than carbon — a real blend defect caught by the render diff in probe J), Element-color fallback cyan. The name matters for **Name coloring** (the default color method): VMD prefix-matches the atom name against a 9-entry table (C→cyan, N→blue, O→red, S→yellow, P→tan, H→white, Z→silver); **mimicking the anchor's name guarantees the same color as the anchor under Name coloring** (identical names resolve identically — no rule knowledge needed), while arbitrary names like "G01" render an unpredictable wrong color (pink/purple/mauve observed). [VERIFIED — probes H/I]

**Primary recommendation:** upgrade `mutation.tcl::_hider_record`/`make_placeholder_hiders` so the simple tier writes `name = anchor.name`, `element = anchor.element`, position = anchor + random-unit-vector × d (d ∈ [1.2, 1.6], default 1.5, rejection-sampled for overlap), keeping resname GAM / beta −999.0 (%6.1f) / segid GAME / chain G / resid 9001 exactly as shipped. Verify headlessly with: numbonds≥1 per hider, element/radius/name equality with the anchor, sentinel round-trip, and the Tachyon render-diff (hider sphere Rad == real-carbon Rad). GUI human-verify: visual blending per rep + click-to-find in each rep.

## 1. Q1 — VMD PDB-load bonding: the distance search, cutoff, scope, and recalc

### 1.1 The search runs automatically on load [VERIFIED — probe A]

`mol new 1znf.pdb` console output (probe A):

```
Info) Using plugin pdb for structure file .../1znf.pdb
Info) Determining bond structure from distance search ...
Info) Analyzing structure ...
Info)    Atoms: 424
Info)    Bonds: 426
```

1znf has **no CONECT records** (only `REMARK LINK`); all 426 bonds come from the distance search. The message "Determining bond structure from distance search" is the definitive console signature of the search running.

### 1.2 The bond law: `d < 0.6 × (r_i + r_j)` [VERIFIED — probes B + C, boundary precision]

Synthetic PDBs with atom pairs at exact distances (100 Å inter-pair spacing, 78-col records via the production format string):

| Pair | radii (r1+r2, ×0.6 = cutoff) | bonded at | not bonded at |
|------|------------------------------|-----------|---------------|
| C–C  | 3.40 → **2.040** | 0.8–2.03 ✓ | 2.05, 2.1, 2.2, 2.5, 3.0 ✗ |
| C–N  | 3.25 → **1.950** | 1.2, 1.6, 1.93 ✓ | 1.97, 2.0, 2.4 ✗ |
| C–O  | 3.22 → **1.932** | 1.91 ✓ | 1.95, 2.0+ ✗ |
| C–S  | 3.50 → **2.100** | 1.6, 2.0, 2.08 ✓ | 2.12, 2.4 ✗ |
| C–H  | 2.70 → **1.620** | 1.0, 1.2, 1.6 ✓ | 1.65 ✗ |

Every one of the 12 boundary cases fits `d < 0.6 × (r_i + r_j)` exactly. Radii are the element VDW radii read back via `atomselect get radius` (C 1.70, N 1.55, O 1.52, S 1.80, H 1.00; unknown element "X" 1.50 — probe A/F). **Consequence:** a GAM hider placed **≤ 1.6 Å** from any C/N/O/S anchor bonds with margin; 1.8 Å works for C/C and C/S but fails for C/N and C/O (1.95/1.93 cutoffs); **2.0 Å is the practical ceiling** (inside C-C 2.04 by 0.04 Å only) — matching v1's "2.0 Å rendering-tolerance ceiling" lesson (11-RESEARCH.md) from a completely independent direction.

### 1.3 Scope of the search: crosses chain/segid/resname/resid boundaries [VERIFIED — probe B]

Group B pairs were `chain A / segid PROT / resname ALA` anchor vs `chain G / segid GAME / resname GAM / resid 1..n` hider: **every pair within cutoff bonded** (numbonds=1 on both atoms, d=1.0–2.0). The search is purely geometric — **the GAME segid does NOT isolate hiders from bonding** (good for blending; note cleanup is never bond-based anyway). GAM–GAM pairs (group A) bond identically to GAM–real pairs at the same distance — no element/resname asymmetry beyond the radii law. Per-resid "Unusual bond between residues" warnings do NOT appear for the synthetic file's same-resid pairs; cross-residue hider bonds in real demos may emit `Warning) Unusual bond between residues: N (none) and M (protein)` — **cosmetic only** (1znf itself loads with two such warnings for its ZN ion, probe A).

### 1.4 Bond existence is queryable headlessly: `numbonds` / `bonded` [VERIFIED — probe A]

Per-atom atomselect attributes on 1.9.3 (probed against the full keyword set):

| attribute | status | semantics |
|-----------|--------|-----------|
| **`numbonds`** | **EXISTS** | integer bond count per atom (`[atomselect $m all] get numbonds`) |
| **`bonded`** | **EXISTS** | 0/1 — has at least one bond |
| `bonds` (bond list) | does NOT exist | "cannot find attribute 'bonds'" |
| `bondcount`, `bondorder`, `order` | do NOT exist | errors |
| selection `bonded to index N` | does NOT exist | "cannot parse selection text" |

`numbonds` is the workhorse: bond existence, extra-bond detection, and anchor-bond-gain checks are all headless-assertable. **There is no way to query WHICH atoms are bonded** (no bond-list attribute) — attribute bonds via arithmetic (anchor numbonds delta) or geometry, never by identity.

### 1.5 `mol bondsrecalc` EXISTS and recomputes from distance [VERIFIED — probe B]

`mol` usage (captured in-run) lists `bondsrecalc <molid> -- Recalculate bonds, current timestep`. Behavior (probe B): after `mol new ... autobonds off` (0 bonds), `mol bondsrecalc $m` printed "Determining bond structure from distance search ..." and rebuilt all 21 bonds (total bond-ends 42). Also present: `reanalyze <molid>` ("Re-analyze structure after changes") — not separately probed. **Use case:** if a future feature edits coordinates post-load, `mol bondsrecalc` refreshes bonds; the PDB-rebuild flow never needs it (bonds are recomputed fresh on every `mol new`).

### 1.6 Load options `autobonds` / `filebonds` [VERIFIED — probes B/D]

`mol new <file> options: type, first, last, step, waitfor, volsets, filebonds, autobonds`:

- **`autobonds off`** disables the distance search: same file loaded with `autobonds off` → `Bonds: 0`, all numbonds=0. [VERIFIED]
- **CONECT records ARE honored** (`filebonds` default on): probe D loaded a pair at 2.6 Å (beyond the 2.04 C-C cutoff) with a `CONECT s1 s2` line → `Bonds: 1`, numbonds=1/1; the identical pair without CONECT → 0/0. [VERIFIED]
- Both sources run together by default (autobonds + filebonds); the "distance search" console message still prints when CONECT is present (D1).

**Design note:** CONECT could *force* exotic bonds, but it is unnecessary for the simple tier — the distance law at ≤1.6 Å is deterministic and geometry-driven. Do not add CONECT to the combined writer (more format surface, zero benefit at 1.5 Å).

## 2. Q2 — GAM atom-record design: element, name, colors, radius

### 2.1 Element drives radius + Element coloring [VERIFIED — probes A/F/H/I/K]

| element field | parsed element | radius | Element-method color | Name-method color (name-mimicked) |
|---|---|---|---|---|
| `C` | C | 1.70 | cyan (0.25,0.75,0.75) | cyan via name prefix "C" |
| `N` | N | 1.55 | blue (0,0,1) | blue via "N…" names |
| `O` | O | 1.52 | red (1,0,0) | red via "O…" |
| `S` | S | 1.80 | yellow (1,1,0) | yellow via "S…" |
| `P` | P | 1.55* | tan | tan via "P…" |
| `H` | H | 1.00 | white | white via "H…" |
| blank/unknown | **X** | **1.50** | cyan (fallback) | **unpredictable** (see 2.3) |

*P read back as 1.55 in probe A (1znf has no P; radius from VMD's element table).

The render-level proof (probe K): hider records with element `C` produced Tachyon spheres with **Rad 0.094504 — byte-identical to the real carbons' Rad in the same scene** — and color cyan. Probe J's buggy records (blank element) produced Rad 0.0833858 = 1.50/1.70 × 0.094504 — **a 12% undersized sphere** that would stand out under VDW/CPK scrutiny. **Rule: the writer MUST always emit the element field (cols 77–78, right-justified), copied from the anchor.**

### 2.2 Name coloring: prefix-match rule + the mimicry guarantee [VERIFIED — probes H/I]

VMD's default color method is **Name**. The Name table (vmd-ref/scripts/colordefs.dat, CITED + probe-verified behavior) has exactly 9 keys: H→white, O→red, N→blue, C→cyan, S→yellow, P→tan, Z→silver, LPA/LPB→green. Probed resolution (Tachyon sphere colors, probes H/I):

- `CA`, `CB`, `C1` → cyan (prefix "C"); `NA`, `N2` → blue; `O1` → red; `S1` → yellow; `H9` → white; `ZN` → silver (prefix "Z"). **Rule: longest matching prefix of the atom name against the table.**
- **Anchor-mimicry guarantee:** identical names always resolve to identical colors — a hider named exactly like its anchor is the same color as the anchor under Name coloring *whatever the rule is*. No rule knowledge required in the implementation.
- Unknown-name fallback is **unpredictable and context-dependent**: "G01" rendered pink (1,0.6,0.6) on one 12-atom molecule and purple (0.65,0,0.65) on a 22-atom one; "XX" mauve; "ZZ" silver; "DUM" lavender; "CU" cyan; "W" ochre (element-like match). The exact fallback is C-source behavior, not further resolvable headlessly — and **irrelevant if names are anchor-mimicked**.
- **Phase-16 hazard quantified:** the shipped placeholder name "G01" does NOT blend under Name coloring (pink vs cyan) — it only blends because the game's own hider reps set `mol modcolor Element` (hiders.tcl). Anchor-mimicked names fix the user-rep path too.

### 2.3 Name also feeds the element guess when the field is blank [VERIFIED — probes C/J]

Blank element field + name `CA` → parsed element **C** (r 1.70); blank + name `G1` → **X** (r 1.50); blank + name `ZN` → **X** (the guesser is not element-table-smart). With the element field present it always wins (probe K: name CA + field C → C). **Both fields mimic the anchor; the element field is the load-bearing one.**

### 2.4 Record spec (compatibility with the shipped writer)

The shipped `mutation.tcl::_hider_record` format string is **correct and reused verbatim** (probe-verified columns; beta %6.1f −999.0, segid GAME cols 73–76, element %2s cols 77–78). The simple tier changes only the *values*: `name` and `element` become the anchor's (Phase 15/16 wrote placeholder name G%02d + element C). Sentinel fields are untouched: `resname GAM` (3 cols), chain G, resid 9001, occ 1.00, beta −999.0. `resname GAM and beta < 0` keeps selecting all hiders after reload (probe J/K: count + beta −999.0 + segid GAME round-trip through writepdb→splice→reload [VERIFIED]).

## 3. Q3 — Geometry: distance, direction, overlap, v1 lessons

### 3.1 Bond-forming distance [VERIFIED — §1.2 law]

- **Recommended band: 1.2–1.6 Å, default 1.5 Å.** Inside every C/N/O/S cutoff with ≥0.33 Å margin; short bonds blend with real bond lengths (C-C 1.5, C-N 1.47, C-O 1.23–1.43); matches v1's 1.0–1.5 Å displacement recommendation (11-RESEARCH.md) and its "2.0 Å ceiling" (here the 2.04 cutoff leaves only 0.04 Å margin at 2.0).
- 1.0–1.2 is also safe but visually very short (stub nearly hidden inside the anchor's VDW sphere under CPK/Licorice ball rendering).
- Never ≥ 1.8 (fails C-N/C-O anchors) and never ≥ 2.04 (fails everything).

### 3.2 Direction [VERIFIED feasibility; design ported from v1]

- **One random unit vector per hider** (11-RESEARCH.md §4d lesson: avoids axis bias; rigid per-hider direction). Pure-layer: `unit_vector(seed-stream)` + `anchor + d * u`.
- **Extra bonds are normal and blend-positive:** the search bonds the hider to EVERYTHING within cutoff, not just the anchor. Probe K on real 1znf anchors: hider numbonds were 4, 4+1(pair), 3, 5 — the Tachyon line-diff showed cyan halves (hider↔C) plus white (hider↔H) and one blue (hider↔N). Visually this reads as an ordinary branching atom — no correction needed, but tests must assert **numbonds ≥ 1**, not == 1.
- **Overlap rejection (the one real hazard):** a hider coincident with a real atom draws a zero-length bond and a buried sphere. The Phase-16 sampler has NO overlap avoidance ("overlapping a real atom is harmless" — true for free-flying VDW spheres, NOT for bonded stubs). Pure-layer rejection: sample candidate = anchor + u×d; reject if any real atom **other than the anchor** is within `min_sep` of the candidate (recommend min_sep 1.2–1.6 Å; also reject cross-hider proximity unless a GAM–GAM stub is intended — probe K proved GAM–GAM bonds form at ≤2.0 Å). Bounded retries with a fallback of relaxing min_sep (a slightly-clashing hider is better than an infinite loop on 3GP6).
- **Coordinate overflow guard:** `%8.3f` maxes at 9999.999 — a coordinate ≥ 10000 shifts the whole line right and **silently corrupts the element field** (probe B "LONE" atom at x=13200 parsed as element X, radius 1.50). Hiders are anchor-relative so this only bites huge-coordinate demos; guard in the pure layer: clamp/reject if |coord| > 9999.0 after offsetting. (Same class as the beta %6.1f-vs-%6.2f overflow pitfall.)

### 3.3 Anchor selection [VERIFIED constraints; choice is policy]

Any real atom works geometrically (search is element-agnostic within the radii law). Policy recommendations: heavy atoms only (`element C N O S P` — H anchors cap the cutoff at 1.62 and H may be absent from some demos); exclude existing GAM atoms; prefer atoms visible in the target scene (all atom-centered reps draw heavy atoms). Pure-layer: the caller feeds an anchor list (index/coords/element/name) — same DI pattern as `sphere_positions(minmax, n)`.

## 4. Q4 — Per-rep rendering behavior of a GAM hider [VERIFIED — Tachyon render probes E/G/H/J/K]

Method: selection-isolated Tachyon renders (`mol modselect` per pair; `axes location off`); primitives counted by type; per-primitive `Rad`/`Color` extracted. Counts per style for the probe-E molecule (P1 = bonded@1.5, P2 = unbonded@2.6, P3 = CONECT-bonded@2.6, LONE = unbonded, elem X):

| style | bonded hider | unbonded hider | lone hider | notes |
|---|---|---|---|---|
| **Lines** | **2 FCylinders** (bond drawn as 2 half-cylinders, hider-half colored by hider) | **1 tiny dot-sphere (Rad 0.002) per atom — unbonded atoms ARE drawn as dots** | 1 dot | a lone hider is NOT invisible in VMD (differs from PyMOL v1!) — but the dot is subtle; bonded is the real feature |
| **Bonds** | 2 FC | dot | dot | same family as Lines |
| **Licorice** | **2 Spheres + 2 FC** (balls at atoms + stick) | 2 dots | 1 dot | ball+stick; defaults read back as bare `Licorice` |
| **CPK** | **2 Spheres + 2 FC** | dots | 1 dot | = VDW + bonds; defaults `CPK` |
| **VDW** | **1 Sphere per atom**, Rad = element radius × scene scale (probe K: hider Rad **0.094504 == real C**; probe E: X 0.075 vs C 0.085, ratio = 1.50/1.70) | 1 sphere | 1 sphere | per-atom; radius table VERIFIED at render level |
| **Points** | 1 dot | 1 dot | **1 dot — lone atoms render** | per-atom rep; easiest tier |
| **DynamicBonds** | 2 FC | **bond drawn if d ≤ rep cutoff** | no primitive | **ignores the bond list**: computes bonds from distance per render using its cutoff param |

**DynamicBonds specifics [VERIFIED — probes E/G]:**
- Valid style name in 1.9.3; read-back echoes params: `DynamicBonds 1.6`, `DynamicBonds 1.6 3.0`. Param 1 = bond distance cutoff; param 2 = bond radius/thickness (render Rad 0.15→0.25 when param2 0→0.5; implied default ≈ 0.3).
- **Default cutoff = 3.0, inclusive** (pairs at 2.6/2.8/3.0 bonded, 3.2 not; explicit `DynamicBonds 3.0` includes exactly-3.0).
- On a **static single-frame molecule** it behaves as a Bonds-style rep with its own cutoff — "bonds appear/disappear on rotation" is a trajectory/frame phenomenon; our molecules are static so the hider stub is stable. The `DynamicBonds` GAME_REPS entry is viable with the same ≤1.6 Å placement (any sane cutoff ≥ 1.6 bonds it).
- Implication: a hider at ≤1.5 Å renders bonded under DynamicBonds **even if `numbonds` were 0** — but keep the numbonds assertion anyway (it certifies Lines/Licorice/CPK, which DO use the bond list).

**Style-name acceptance [VERIFIED — probe C/D]:** `mol modstyle` accepted bare `Lines`, `Bonds`, `Licorice`, `CPK`, `VDW`, `Points`, `DynamicBonds` (read-backs echo the name; params optional). **Pitfall found:** `mol modstyle <repid out of range>` **silently no-ops** (no error; `molinfo get "rep N"` then errors "rep N out of range") — rep-index guards (hiders.tcl pattern) are mandatory.

**What still needs the GUI:** whether these Tachyon-exported primitives match the OpenGL display 1:1 (expected yes — same display-list source; ASSUMED→GUI-confirm), actual visual blending quality, and the unbonded-dot's prominence on screen.

## 6. Q6 — Blending assessment: what is headless vs GUI

### 6.1 Headless-verifiable (all demonstrated in tmp/p17-research-b)

1. **Bond existence:** `[atomselect $g "resname GAM and beta < 0"] get numbonds` — every hider ≥ 1 (probe K: 4,4,3,5).
2. **Anchor bond-gain:** anchor `numbonds` increased by the hider's bond count (probe B pattern).
3. **Element/radius/name equality with anchor:** `get {element}` / `get {radius}` / `get {name}` vs the anchor's values (probe K: C/1.70/CA == anchor).
4. **Sentinel round-trip:** after writepdb→splice→`mol new`: `resname GAM and beta < 0` count == hiders, betas −999.0, segids GAME (probes J/K).
5. **Render-diff (the blend proof):** `render Tachyon` twice — rep selection `all` vs `not resname GAM` — the diff contains EXACTLY the hider primitives; assert hider sphere **Rad == the real-element Rad in the same scene** and **Color == the real-element color** (probe K: 4× Rad 0.094504 + cyan = perfect). Lines diff: added FCylinders whose hider-half color == element color. **Caveats:** `mol showrep off` is IGNORED in text mode (probe F6 — use selection isolation, never showrep); scene coordinates are view-scaled so compare Rad/Color, never positions; Tachyon merges collinear half-bonds so FC counts are approximate — assert presence + colors, not exact counts.
6. **Style acceptance:** `mol modstyle` + read-back per GAME_REPS entry (bare names all accepted).
7. **Coordinate bounds** (pure layer): |x|,|y|,|z| ≤ 9999.0 post-offset.

### 6.2 GUI human-verify (minimum checklist)

1. Lines scene: hider stubs indistinguishable from real bonds at a glance (the core HIDER-04 acceptance).
2. Licorice / CPK / VDW / Points / DynamicBonds scenes: same per rep.
3. Click a hider in each rep → find registers (esp. clicking a *line stub*, not a sphere).
4. Name-colored user scene vs Element-colored scene both blend (mimicry working in both paths).
5. Unbonded-dot prominence (only relevant as a degraded case).

## 7. Q7 — Single-atom vs multi-atom hiders

**Single-atom-per-hider is sufficient for the simple tier** (recommendation):

- A single bonded GAM renders as a line stub in Lines/Licorice/Bonds/DynamicBonds and a sphere in VDW/CPK/Points — every target rep is satisfied (§4). v1 shipped exactly this for lines/stick (05-RESEARCH.md Q2).
- Extra visual mass comes free via multi-bonding to nearby real atoms (probe K: numbonds up to 5) — no second atom needed.
- **Multi-atom hiders complicate the found-marking flow:** the shipped hidden/found reps partition PER-ATOM on `user2` (`... and user2 < 1` / `user2 > 0` — sentinel selectors, hiders.tcl). A 2-atom hider found via one index leaves the partner atom in the hidden rep (still rendered as unfound) unless mark_found flags BOTH indices — a registry/visual contract change. Registry records stay 1-per-hider (counts unaffected), but pick-any-atom-of-the-pair scoring needs either dual registration or partner lookup. Probe K verified the *rendering* works (CB–CG stub, GAM-GAM + GAM-real bonds at 1.4 Å each) — the mechanism is available if a later phase wants bigger features; do NOT build it into 17.1.

## 8. PITFALLS discovered (all probe-verified this session)

1. **Blank/overflowed element field → silent element X** (radius 1.50 = 12% undersized vs C; unpredictable Name color). Caught by render-diff Rad comparison (probe J vs K). Prevention: always emit cols 77–78 from the anchor; assert element equality post-load.
2. **Coordinate ≥ 10000 breaks the %8.3f field** — line shifts right, sentinel/element columns corrupt (probe B LONE atom). Guard |coord| < 9999 in the pure layer.
3. **`mol modstyle` on an out-of-range rep index silently no-ops** (probe C4) — guard rep indices before mod* calls (hiders.tcl already does).
4. **`mol showrep off` is ignored in `-dispdev text`** (probe F6) — headless isolation must use selection isolation; don't write text-mode tests that rely on rep hiding.
5. **`atomselect get {kw1 kw2}` returns per-atom LISTS** — `lassign` flat-splits wrongly (probe J's blank-element bug originated here). Use one keyword per `get`, or `lindex` the nested result. (Affects game code style too — mutation.tcl/hiders.tcl currently use single-keyword gets: safe.)
6. **`numbonds > 1` is NORMAL** for hiders in crowded regions — assert ≥ 1, never == 1.
7. **VMD -e swallows statement errors and continues** — twice this session a broken statement silently produced a near-empty/false-pass run (probe B first draft; probe J's anchor loop). Every probe (and every headless smoke) must end with hard `error` guards on expected counts.
8. **Name-coloring fallback for arbitrary names is unpredictable** (pink/purple/mauve/silver observed; same name varied across molecules) — mimic the anchor name; never ship placeholder names in blending tiers.
9. **"Unusual bond between residues" warnings on load** (GAM restype "none" bonding to protein) — cosmetic; don't treat as failure in smoke output scanning.

## 9. Recommendations for the planner

### 9.1 GAM atom-record spec (simple tier) — the deliverable

```
ATOM  %5d %4s%1s%-3s %1s%4d%1s   %8.3f%8.3f%8.3f%6.2f%6.1f      %-4s%2s
      serial name alt resname chain resseq icode X Y Z occ beta segid elem

serial   = orig_n + 1 + i            (continues writepdb serials)
name     = anchor.name               (≤4 chars; %4s right-justified as shipped)
```
