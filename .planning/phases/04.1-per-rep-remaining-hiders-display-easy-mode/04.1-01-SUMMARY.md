## Decisions Made
- **Mirror `counts_by_rep` with one filter line** (vs. a new abstraction): the plan's `<implementation>` sketch was followed verbatim in structure — `out = {rep: 0 for rep in GAME_REPS}` + iterate + `if r.rep is None: continue` + ONE new line `if r.status == HIDER_STATUS_HIDDEN:` + increment. Minimal diff, maximal reviewability, zero cleverness.
- **SC3 "sums to remaining" contract scope**: the contract holds in the normal game flow where `register()` always passes a valid rep (no `rep=None` records). The `rep=None` skip is a SEPARATE defensive behavior for the post-`.pse`-reload case (sentinel carries no rep; Phase 8 `.bcm` sidecar reconciles). The unit tests correctly test these as separate scenarios (test #5 `test_remaining_by_rep_sums_to_remaining` uses only valid-rep records; test #6 `test_remaining_by_rep_skips_rep_none` tests the rep=None ghost skip independently).
- **REFACTOR skipped**: the GREEN phase already produced clean code (the class docstring already names `remaining_by_rep` as the hidden-filtered counterpart, which was the plan's example of "obvious cleanup"). No commit per the plan's "If no cleanup is needed, SKIP the commit" instruction.
- **Docstring written in PROSE**: "no pymol import, no Qt" (not literal `from pymol import cmd`) to avoid the AGENTS.md-documented Pitfall-1 grep false-positive pattern — mirrors the 03-02/06/09/10 precedent. Verified: PURITY gate + Pitfall-1 gate both return zero matches.
