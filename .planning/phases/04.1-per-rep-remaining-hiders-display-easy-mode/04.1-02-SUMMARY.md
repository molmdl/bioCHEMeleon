# Phase 4.1 Plan 02: Per-rep Remaining Hiders Display Summary

**Pure `format_remaining(total, counts_by_rep, easy_mode)` label formatter in setup_state.py — hard mode stays total-only (SC2), easy mode appends a GAME_REPS-ordered per-rep parenthetical with a two-space separator (SC1).**

## Accomplishments

- Added `format_remaining(total, counts_by_rep, easy_mode)` to `setup_state.py` behind a `# ---- Remaining-hiders label formatter (Phase 4.1, GAME-03) ----` section comment — pure (stdlib + `GAME_REPS`), no Qt, no molecular-viewer coupling, WSL-unit-testable.
- Hard mode is byte-identical to the Phase 4 label: `format_remaining(7, {...}, False)` == `"Remaining: 7"` (SC2).
- Easy mode appends the per-rep breakdown in `GAME_REPS` order, keeping only reps whose count > 0, with exactly two spaces before the paren: `format_remaining(7, {'spheres':2,'sticks':3,'cartoon':2}, True)` == `"Remaining: 7  (sticks: 3, spheres: 2, cartoon: 2)"` (SC1).
- Safe-degrades to total-only on `None`/empty counts dicts and on the all-zero win state — the label never shows an empty parenthetical.
- Added `TestFormatRemaining` (8 tests) covering hard mode, easy-mode mixed, zero-filtering, all-zero win state, None counts, empty dict, two-space separator, and GAME_REPS-ordering (insertion-order anti-GAME_REPS input → GAME_REPS-order output).

## Decisions Made

- **Kept the reference sketch verbatim / skipped REFACTOR.** The plan's implementation sketch was already the clean form; the only candidate cleanup (DRY-ing the `"Remaining: %d" % total` literal) doesn't fully DRY because the final return embeds the `"Remaining: "` prefix, so extracting a local would trade readability for micro-DRY. Per the plan's "If no cleanup needed, SKIP the commit", no refactor commit was made.
- **Docstring in prose.** AGENTS.md documents that docstrings containing literal `from pymol` / `.exec_()` tokens trip the Pitfall-1 grep gate. The `format_remaining` docstring is written in prose (mirrors the 03-02/06/09/10 precedent) and passed both the PURITY and Pitfall-1 gates with zero matches.
- **Defensive `.get(rep, 0)` in the comprehension.** The caller's counts dict is expected to be zero-filled (like `registry.remaining_by_rep`), but `.get` guards a sparse dict so a missing key is treated as zero rather than raising `KeyError`.
