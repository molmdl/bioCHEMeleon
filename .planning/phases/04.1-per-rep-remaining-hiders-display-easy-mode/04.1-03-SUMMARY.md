## Decisions Made

- **Option b plumbing (caller-set duck-typed attribute).** Chose the 1-line `_easy_mode` set in `__init__.py:_continue_after_large_demo_fetch` over adding it to `game.py:GameController.__init__`. Rationale: keeps the change minimal (avoids a 4th file), covers both fresh-game paths via the shared post-fetch entry point, and matches the `_found_color` precedent (duck-typed attribute set by the caller). The `getattr` default in the GUI handles imported games / restart paths.
- **Option c pull model (no callback change).** Chose to rewrite `_update_remaining` to PULL `remaining_by_rep()` + `_easy_mode` at render time over threading counts through the `on_remaining_changed` callback. Rationale: zero callback signature change → zero game.py fire-site change → zero `set_callbacks` change → Phase 6/7/8 consumers, the 257 WSL unit tests, and the smoke lambdas all stay green. This is the single biggest reason the plan has zero backward-compat breakage.
- **`getattr` default False + short-circuit.** `easy_mode = getattr(self._controller, '_easy_mode', False)` and `counts = ... if easy_mode else None` — imported games (out of scope for 4.1) and any controller without the attribute degrade to total-only (Phase 4 hard-mode behavior). Also null-safe if `self._controller` were None and skips the registry access in hard mode.
- **Leave the `:786` reset string total-only.** The IDLE/reset label `self.game_tab._remaining_label.setText("Remaining: -")` is intentionally left as total-only — per-rep only matters during active play, not the idle/reset state.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Smoke hider_specs payload shape updated to Phase 5/11 rep-specific contract**

- **Found during:** Task 2 (Headless smoke for the remaining_by_rep read path)
- **Issue:** The plan's Task 2 spec called for `hider_specs = [(pos, "spheres"), ...]` using `[x,y,z]` coords for ALL reps — that is the Phase 4 spheres-only contract. Phase 5 (05-04) changed `hider_specs` to rep-specific payloads (`(offset, neighbor_id)` for sticks; `(chain, terminus_resi, is_c_terminus)` 3-tuple for cartoon) routed by the `insert_hider_for_rep` dispatcher. A `[x,y,z]` payload for sticks/cartoon would crash the dispatcher unpack and the smoke would never reach `start()`.
- **Fix:** Built the mixed-rep `hider_specs` the same way `phase5_smoke.py` section 4 does — rep-specific payloads via `generators.generate_sphere_positions` (spheres), `(generators.generate_line_stick_offsets(...)[0], neighbor_id)` (sticks), and `generators.pick_terminal_residues(...)` 3-tuple (cartoon, the legacy terminal-extension path the dispatcher maintains backward-compat with). This tests the SAME data path the plan intended (`remaining_by_rep` is rep-agnostic — it just counts registry records by rep, regardless of payload shape).
- **Files modified:** `smoke/phase4_1_smoke.py` (the new smoke; NO product code changed — `registry.py` / `game.py` / `gui_game.py` / `__init__.py` untouched by this deviation)
- **Verification:** Headless run `cd tmp/bioCHEMeleon && timeout 90 cmd.exe /c "C:\\src\\run-conda-pymol.bat -cq smoke\\phase4_1_smoke.py" 2>&1 | tail -50` → 18/18 PASS, exit 0. The mixed-rep start + per-rep decrement assertions all pass.
