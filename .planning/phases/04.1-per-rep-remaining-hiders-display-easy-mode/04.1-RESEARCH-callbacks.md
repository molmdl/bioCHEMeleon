## 2. Three-Option Evaluation (delivering per-rep counts to the GameTab label)

### ⚠️ Critical data-source finding (applies to ALL 3 options)

**`registry.counts_by_rep()` (registry.py:244-264) counts ALL records, NOT just hidden ones.** Quoting registry.py:259-264:
```python
out = {rep: 0 for rep in GAME_REPS}
for r in self._records.values():
    if r.rep is None:
        continue
    out[r.rep] = out.get(r.rep, 0) + 1   # NO status filter — counts hidden + found
return out
```
SC1's example `"Remaining: 7  (spheres: 2, sticks: 3, cartoon: 2)"` requires the per-rep numbers to be REMAINING (hidden-only) counts — they must sum to the total remaining (2+3+2=7). `counts_by_rep()` returns TOTAL per-rep (hidden+found), so it would show "spheres: 3" even after 2 are found, while the total says "Remaining: 1" — inconsistent and wrong for SC3.

**Conclusion:** The per-rep display CANNOT use `registry.counts_by_rep()` directly. A hidden-filtered per-rep source is REQUIRED. Recommended: add `registry.remaining_by_rep()` (pure, mirrors `counts_by_rep` but filters `status == HIDER_STATUS_HIDDEN`; skips `rep=None`). **This data-source method is the plumbing researcher's territory** — flag for reconciliation. The callback/label design below assumes such a source exists; the exact method name is a planning detail.

**Live-game assumption (rep=None caveat):** During a live game (fresh `start()`), all records have valid reps (`game.py:87` passes `rep=rep` from `hider_specs`; `register` validates `rep in GAME_REPS` per registry.py:111-112). `rep=None` only arises after `.pse` reload via `reconstruct_from_sentinels` (registry.py:405), and Phase 8's `reconcile_with_bcm` (registry.py:411-474) restores reps before play resumes. So during live play, a hidden-filtered per-rep dict is accurate. Edge case: a corrupt `.bcm` with `bad_rep` (registry.py:452-454) leaves some records `rep=None` → those hidden hiders are clickable (in registry, counted by `_remaining()`) but invisible to per-rep counts → label shows `Remaining: 5  (spheres: 3)` where per-rep sum (3) < total (5). This is acceptable degraded display (same limitation class as `counts_by_rep`'s documented `rep=None` skip at registry.py:261-262). The pure helper must handle `sum(per_rep) < total` gracefully (it just formats whatever dict it's given — see §4).

## 3. Recommendation — Option (c), Pull Model

**Recommended:** Option (c). The GameTab's `_update_remaining` reads `self._controller.registry.remaining_by_rep()` (hidden-filtered per-rep dict) + `self._easy_mode` directly, formats via the pure helper, and sets the label. NO changes to `game.py` fire sites, NO `set_callbacks` signature change, NO new callback slot. Zero backward-compat breakage.

### Exact changes

#### `set_callbacks` signature — **NO CHANGE**
`game.py:94-111` stays exactly as-is. The 4 existing callbacks + their defaults are untouched.

#### Fire sites in game.py — **NO CHANGE**
`game.py:188` (`self._on_remaining_changed(remaining)` in `on_pick`), `game.py:294` (in `reveal_one`), `game.py:316` (in `reveal_all`) all stay 1-arg. The per-rep data is PULLED by the GUI at render time, not PUSHED by the controller.

#### `_update_remaining` in gui_game.py — **CHANGE (1 method body)**
Current (`gui_game.py:98-99`):
```python
def _update_remaining(self, remaining):
    self._remaining_label.setText("Remaining: %d" % remaining)
```
Proposed:
```python
def _update_remaining(self, remaining):
    # Pull the hidden-filtered per-rep dict at render time (post-find state).
    # remaining_by_rep() is the hidden-only source (registry skips rep=None).
    # self._easy_mode is plumbed by work item 1 (the other researcher).
    counts_by_rep = self._controller.registry.remaining_by_rep()
    self._remaining_label.setText(
        format_remaining(remaining, counts_by_rep, self._easy_mode))
```
**Notes:**
- `format_remaining` imported via `from .setup_state import format_remaining` (pure helper, §4).
- `self._controller.registry.remaining_by_rep()` — the new pure registry method (flagged in §2; plumbing researcher's territory). Falls back to `counts_by_rep()`-style `{rep: 0}` zero-fill if no hidden hiders.
- `self._easy_mode` — set by work item 1 (the other researcher). Likely a GameTab attribute set in `start_countdown` from the plumbed `difficulty_easy`. This doc does NOT design that plumbing; it only requires that `_easy_mode` is readable when `_update_remaining` runs (which is on every find, well after `start_countdown`/`_begin_play`).
- If `self._easy_mode` is not yet set (defensive), `getattr(self, '_easy_mode', False)` avoids AttributeError on a pre-countdown state. Recommend the planner include this defensive read.

#### Why (c) over (a)/(b) — recap
- (a) breaks `test_game_controller.py:618,659` + `phase4_smoke.py:48` + `phase6_smoke.py:48`.
- (b) adds a 5th callback + a new GUI slot + splits label logic across 2 fire sequences — strictly more surface than (c) for the same outcome.
- (c) changes 1 method body, breaks nothing, uses an established GUI→registry precedent (`gui_game.py:149`).

## 4. Pure Formatting Helper (TDD candidate — WSL unit-testable)

### Proposed location: `biochemeleon/setup_state.py`

**Rationale:**
- `setup_state.py` is the established PURE layer (stdlib only — NO `pymol`, NO `Qt`; setup_state.py:1-12 docstring). Already holds `GAME_REPS` (setup_state.py:23) which the helper iterates.
- WSL-unit-testable alongside the existing 90 `tests/test_setup_state.py` tests (AGENTS.md: "Pure functions → setup_state.py + unit tests").
- `gui_game.py` can import it cleanly: `from .setup_state import format_remaining` (no circular import — setup_state imports nothing from biochemeleon; it's the base of the dependency chain per AGENTS.md: `setup_state ← demos ← gui_setup`, `setup_state ← registry ← game`).
- Rejected alternatives: `registry.py` (mixes data-model + UI-formatting concerns); a new `formatting.py` (overkill for one function; adds a file + import path to maintain).

### Exact signature
```python
def format_remaining(total, counts_by_rep, easy_mode):
    """Format the remaining-hiders label (GAME-03 per-rep display, easy mode).

    Pure (stdlib only — no pymol, no Qt). WSL-unit-testable.

    Args:
        total (int): total remaining (hidden) hiders, from GameController._remaining()
            (game.py:113-116 — counts records with status == 'hidden').
        counts_by_rep (dict or None): {rep: count} of REMAINING (hidden-only) hiders
            per rep, from registry.remaining_by_rep() (hidden-filtered; skips
            rep=None records — registry.py:261-262 precedent). None or empty
            -> total-only display. NOTE: this is NOT registry.counts_by_rep()
            (which counts ALL records incl. found — registry.py:244-264);
            the caller must pass a HIDDEN-filtered dict.
        easy_mode (bool): True = easy (show per-rep breakdown); False = hard
            (total-only, unchanged from Phase 4 — SC2).

    Returns:
        str: the label text.
          - easy_mode False OR counts_by_rep None -> "Remaining: {total}"
            (Phase 4 behavior; SC2).
          - easy_mode True, all per-rep counts 0 -> "Remaining: {total}"
            (win state — no parenthetical).
          - easy_mode True, some per-rep > 0 ->
            "Remaining: {total}  ({rep}: {count}, {rep}: {count}, ...)"
            with TWO spaces before the parenthetical (SC1 example), reps in
            GAME_REPS order (setup_state.py:23), only reps with count > 0.
    """
```

### Exact output format (matching SC1)
SC1 example: `"Remaining: 7  (spheres: 2, sticks: 3, cartoon: 2)"`

| Element | Spec |
|---------|------|
| Prefix | `"Remaining: "` |
| Total | `{total}` (int) |
| Separator before parenthetical | **TWO spaces** (`"  "`) — per SC1 + task spec |
| Parenthetical open | `"("` |
| Per-rep entries | `"{rep}: {count}"` (colon + space) |
| Per-rep separator | `", "` (comma + space) |
| Parenthetical close | `")"` |
| Rep ordering | `GAME_REPS` order (`['lines','sticks','spheres','cartoon','ribbon']`, setup_state.py:23) |
| Rep filtering | ONLY reps with `count > 0` (matches SC1 showing 3 of 5 reps — see §4 note) |

### ⚠️ Ordering discrepancy flag (MEDIUM confidence — planner/user decision)
The SC1 example shows `"spheres: 2, sticks: 3, cartoon: 2"` (spheres BEFORE sticks), but `GAME_REPS` order is `['lines','sticks','spheres','cartoon','ribbon']` (sticks BEFORE spheres). The task spec says "in `GAME_REPS` order" AND "matching SC1's example" — these conflict.

**Recommendation:** Follow `GAME_REPS` order (codebase consistency — every other per-rep iteration uses it, e.g. `counts_by_rep` zero-fill at registry.py:259, `group_found_by_rep` consumers). Output would be `"Remaining: 7  (sticks: 3, spheres: 2, cartoon: 2)"`. The SC1 example is treated as illustrative of the FORMAT (prefix, two-space separator, parenthetical, colon-space, comma-space), not the exact rep ORDER. **The planner should confirm with the user if rep order must exactly match the SC1 example (spheres-first) — if so, the helper needs a custom order, but that breaks codebase consistency.** Default to GAME_REPS order unless the user says otherwise.

### The 4 behaviors

| # | Condition | Output | SC satisfied |
|---|-----------|--------|--------------|
| (i) | `easy_mode=False` | `f"Remaining: {total}"` (Phase 4 behavior, unchanged) | SC2 |
| (ii) | `easy_mode=True` AND `counts_by_rep` has reps with count>0 | `f"Remaining: {total}  ({rep}: {count}, ...)"` (GAME_REPS order, count>0 only) | SC1, SC3 (via fresh dict per find) |
| (iii) | `counts_by_rep=None` (or empty/falsy) | `f"Remaining: {total}"` (treat as total-only — safe default; same as easy_mode=False) | SC2 (degraded) |
| (iv) | `easy_mode=True` BUT all per-rep counts are 0 (win state / no hiders) | `f"Remaining: {total}"` (no empty parenthetical — clean win-state display) | SC1 graceful |

### Reference implementation sketch (for TDD RED step)
```python
def format_remaining(total, counts_by_rep, easy_mode):
    if not easy_mode or not counts_by_rep:
        return "Remaining: %d" % total
    parts = ["%s: %d" % (rep, counts_by_rep[rep])
             for rep in GAME_REPS if counts_by_rep.get(rep, 0) > 0]
    if not parts:
        return "Remaining: %d" % total
    return "Remaining: %d  (%s)" % (total, ", ".join(parts))
```
- Uses `%` formatting (matches codebase style — `gui_game.py:99`, `game.py:187`).
- `counts_by_rep.get(rep, 0)` defensive (caller's dict should be zero-filled like `counts_by_rep`, but `.get` guards a sparse dict).
- `GAME_REPS` imported at module top of `setup_state.py` (already there — setup_state.py:23).
