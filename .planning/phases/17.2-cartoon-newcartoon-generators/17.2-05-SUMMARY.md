## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Scene-diff blanket `not resname GAM` polluted scene B**
- **Found during:** Task 1 (first staged run)
- **Issue:** With the hider reps present (plan order: hiders step 3, renders
  step 4), the scene-diff's blanket per-rep `not resname GAM` turned the
  EMPTY found rep (selection `resname GAM ... user2 > 0 ...`, zero atoms)
  into a REAL-ATOM Cartoon rep -- scene B rendered MORE than scene A
  (A=865 vs B=964, delta=-99 vs floor 60). The 17.2-04 harness never hit
  this because it renders BEFORE any hider reps exist.
- **Fix:** PER-REP fake removal in the scene-diff: a rep whose CURRENT
  selection string contains `resname GAM` empties to `index 999999`; all
  other reps go `not resname GAM`. Verified: delta 112/123/110 >= floors.
- **Files modified:** vmd/smoke/phase17_cartoon_smoke.tcl
- **Verification:** 3 consecutive PASS=1 runs (evidence above)
- **Committed in:** 9075dc4

**2. [Rule 3 - Blocking] _render_bits "restore to all" would wipe hider reps**
- **Found during:** Task 1 (design, before first run)
- **Issue:** The 17.2-04 _render_bits helper restores every earlier rep to
  `all` after a render -- byte-identical when every prior selection IS
  "all", but it would WIPE the hider reps' user3-conjoined tier selections
  (they exist during this smoke's renders per the plan's step order).
- **Fix:** Exact-restore adaptation: grab every rep's selection via the
  combined-braces molinfo form (`_sel_grab`), restore verbatim after the
  render. Identical behavior for 17.2-04-style molecules.
- **Files modified:** vmd/smoke/phase17_cartoon_smoke.tcl
- **Verification:** post-render read-back asserts (style `Cartoon` exact,
  selections verbatim) pass in all 3 runs
- **Committed in:** 9075dc4
