<objective>
TDD `HiderRegistry.reconstruct_from_sentinels(iterate_hider_keys)` — the post-reload registry rebuild via dependency injection — plus the registry edge cases (duplicate id, bad rep, rep=None tolerance for reconstruction).

Purpose: After a `.pse` reload, the in-memory registry is lost but the sentinel atoms survive (RESEARCH §Q4 MEDIUM flag). `reconstruct_from_sentinels` rebuilds the registry from the sentinel atoms' `(object, id)` tuples. The iterate function is INJECTED as a parameter (dependency inversion) so `registry.py` stays pure — no `from pymol import cmd`. After reconstruction, `rep` is unknown (the sentinel carries no rep — RESEARCH Open Risk 6) and is set to `None`; the registry must tolerate `rep=None` ONLY in the reconstruction path (not in normal `register`, which validates against GAME_REPS). Phase 8's `.bcm` sidecar recovers `rep` later.
Output: registry.py extended with `reconstruct_from_sentinels` (DI-based, rep=None tolerance); tests cover reconstruction + all edge cases. registry.py is now functionally complete for Phase 3.
</objective>

  <name>reconstruct_from_sentinels + edge cases (dup id, bad rep, rep=None)</name>
  <files>biochemeleon/registry.py, tests/test_registry.py</files>
  <behavior>
    HiderRegistry.reconstruct_from_sentinels(iterate_hider_keys):
      - clears existing records (self._records.clear())
      - for each (object, id) in iterate_hider_keys(): registers a HiderRecord with rep=None, status='hidden'
      - rep=None is ALLOWED here (bypasses the GAME_REPS validation) — the sentinel carries no rep
      - returns self (fluent)
    Edge cases:
      - register with rep='surface' (not in GAME_REPS) -> raises ValueError (already tested in 03-01, reconfirm)
      - register with duplicate (object, id) -> raises KeyError (already tested in 03-01, reconfirm)
      - reconstruct_from_sentinels with a fake iterate_fn returning [('1ubq', 1), ('1ubq', 2)] -> registry has 2 records, both rep=None, status='hidden'
      - reconstruct_from_sentinels with empty iterate_fn -> registry is empty (cleared)
      - reconstruct_from_sentinels overwrites existing records (clear then rebuild)
      - after reconstruction, by_rep(None) returns all records (rep is None); counts_by_rep() does NOT include rep=None (only GAME_REPS keys — records with rep=None are invisible to counts_by_rep, documented limitation)
  </behavior>
  <implementation>
    Follow 03-RESEARCH.md §"Registry Design" sketch (lines 218-227):
    ```python
    def reconstruct_from_sentinels(self, iterate_hider_keys):
        """Rebuild registry from sentinel atoms after .pse reload.
        iterate_hider_keys: callable -> iterable of (object, id) for segi-GAME b--999 atoms.
        Pure: cmd-coupled iterate is INJECTED by game.py. rep is unknown post-reload
        (set to None pending Phase 8 sidecar reconciliation)."""
        self._records.clear()
        for (obj, aid) in iterate_hider_keys():
            self._records[(obj, int(aid))] = HiderRecord(aid, obj, rep=None,
                                                          status=HIDER_STATUS_HIDDEN)
        return self
    ```
    CRITICAL: `HiderRecord.__init__` currently validates `rep in GAME_REPS` and raises ValueError for invalid reps. `rep=None` would raise ValueError. So EITHER:
    (a) Add an optional `validate_rep=True` parameter to HiderRecord.__init__ and pass `validate_rep=False` in reconstruct_from_sentinels, OR
    (b) Allow `rep=None` in the validation: `if rep is not None and rep not in GAME_REPS: raise ValueError(...)`.
    Choose (b) — simpler: `if rep is not None and rep not in GAME_REPS: raise ValueError(...)`. This allows `rep=None` everywhere but `register()` (the normal path) always passes a valid rep, so the relaxation only affects reconstruction. Document this in the HiderRecord docstring.
  </implementation>
