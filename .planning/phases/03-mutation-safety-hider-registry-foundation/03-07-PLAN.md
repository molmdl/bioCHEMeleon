<feature>
  <name>HiderRegistry serialization: to_dict / from_dict round-trip</name>
  <files>biochemeleon/registry.py, tests/test_registry.py</files>
  <behavior>
    HiderRegistry.to_dict() -> {'version': 1, 'hiders': [record.to_dict() for each record in insertion order]}
    HiderRegistry.from_dict(d) -> new HiderRegistry with all hiders registered (classmethod)
    Round-trip: registry A -> to_dict() -> from_dict() -> registry B; B.all() matches A.all() (same ids, objects, reps, statuses, positions)
    Cases:
      - empty registry: to_dict() -> {'version': 1, 'hiders': []}
      - 3 hiders with mixed reps + one with pos: to_dict() has version=1, hiders list of 3 dicts
      - round-trip: register 3, to_dict, from_dict, new registry has same 3 records (same keys, same fields)
      - from_dict with missing 'version' key: still works (defaults to treating as v1)
      - from_dict with missing 'status' in a hider: defaults to 'hidden'
      - from_dict with 'pos' as list [x,y,z]: converts to tuple in the record
  </behavior>
  <implementation>
    Follow 03-RESEARCH.md §"Registry Design" sketch (lines 228-236):
    - `def to_dict(self):` return `{'version': 1, 'hiders': [r.to_dict() for r in self._records.values()]}`
    - `@classmethod def from_dict(cls, d):` `reg = cls()`; for each `h` in `d.get('hiders', [])`: `reg.register(h['object'], h['id'], h['rep'], h.get('status', 'hidden'), h.get('pos'))`; return reg
    Note: `h.get('pos')` returns a list from JSON; the HiderRecord stores it as-is (list). That's fine for serialization — Phase 8 handles the list/tuple conversion at the boundary. Phase 3 only tests the round-trip is value-preserving.
  </implementation>
</feature>
