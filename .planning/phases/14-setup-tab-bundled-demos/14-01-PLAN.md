<feature>
  <name>Setup-state model (validate + randomize)</name>
  <files>vmd/lib/setup_state.tcl, vmd/tests/test_setup_state.test</files>
  <behavior>
    Three coupled pure functions sharing helpers + the global tcl 8.5 PRNG:
    - validate_state {state {atom_count {}}}: deterministic clamp. Fills missing keys from DEFAULTS, clamps hider_count to [1, cap] (cap = hider_count_cap(atom_count) or 50), drops invalid per_rep keys (not in GAME_REPS) + zero/negative counts, clamps per_rep sum to <= hider_count via INSERTION-ORDER DROP-OVERFLOW (never truncates — Pitfall 7 in research), validates enums (target_mode/demo_id), coerces bools, validates pdb_pool (dedupe + 4-char lowercase). Returns a NEW dict in DEFAULTS key order. NO randomness.
    - randomize_per_rep {hider_count game_reps {seed {}}}: quick-008 pure helper. Distributes hider_count across a RANDOM NON-EMPTY SUBSET (1..len) of game_reps via Fisher-Yates _sample. Guarantees >=1 rep with count > 0 when hider_count > 0. seed -> deterministic.
    - randomize_state {{seed {}} {atom_count {}} {lock_source 0} {locked_state {}} {pdb_pool {}}}: returns a complete 11-key dict. Seeds once at top (if seed), calls randomize_per_rep with NO seed (continues sequence). lock_source=1 preserves the locked_state's target; else random mode (weighted toward demo; empty pdb_pool -> fetch re-rolls to demo).
    Cases (all use explicit seeds — Pitfall 4: global PRNG): see 14-RESEARCH-mol-logic.md lines 656-689 (~28 cases in 3 groups).
  </behavior>
  <implementation>
    Verified skeletons in 14-RESEARCH-mol-logic.md:
